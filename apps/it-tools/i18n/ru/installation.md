# Установка IT Tools

Нужны Docker Engine, Compose >=2.24, 1 CPU, 64 МБ RAM (128 МБ рекомендуются) и 1 ГБ диска для образа. Проверен amd64; образ также публикует arm64.

```sh
cp .env.example .env
docker compose up -d --wait
```

Откройте `http://127.0.0.1:8084`. Входа нет. Для удалённого сервера: `ssh -L 8084:127.0.0.1:8084 user@server`.

## Переменные

- `IT_TOOLS_VERSION`: явный официальный тег `2024.10.22-7ca5933`.
- `IT_TOOLS_PORT`: HTTP-порт loopback, по умолчанию `8084`.
- `IT_TOOLS_BACKUP_DIR`: необязательный каталог backup, иначе `./backups`.

Файл `config/nginx.conf` задаёт непривилегированный порт контейнера 8080 и временные файлы в `/tmp`. Он доступен UID 101 только для чтения. Приложение статическое: добавление runtime VITE-переменных не меняет сборку.

<!-- coverage:deployment-vps -->
## VPS

На VPS оставьте порт закрытым firewall. Открывайте через SSH-туннель, VPN либо отдельно защищённый HTTPS-шлюз.

<!-- coverage:deployment-lan -->
## LAN / VPN

Для домашней сети используйте туннель или VPN-прокси. Публикация интерфейса даёт доступ всем, кого пропускает сеть; аккаунтов нет.

<!-- coverage:deployment-domain-https -->
## HTTPS

Задайте DNS и настройте прокси из примеров ниже. Рецепт остаётся на loopback; HTTPS сам по себе не добавляет вход.

<!-- coverage:proxy-caddy -->
## Caddy

В `proxy/Caddyfile` замените домен и порт. Пример для Caddy на том же хосте, с автоматическим TLS.

<!-- coverage:proxy-nginx -->
## Nginx

В `proxy/nginx.conf` замените домен, порт и пути TLS-сертификатов. Это внешний прокси, отдельно от статического сервера контейнера.

<!-- coverage:proxy-traefik -->
## Traefik

Подключите `proxy/traefik.yaml` к file provider, с websecure и letsencrypt. Для контейнерного прокси отдельно настройте сеть: его loopback не указывает на хост.

<!-- coverage:data -->
## Data / Данные

Сервер хранит только env, Compose и config/nginx.conf. Избранное, язык, тема и часть ввода находятся в local storage браузера. Не считайте серверный backup копией браузерных данных.

<!-- coverage:backup -->
## Backup

Запустите `./backup.sh`. Он архивирует config, env и Compose без остановки статического сервера. Храните внешнюю копию; если добавили секреты, шифруйте архив. Браузерный профиль сохраняется отдельно.

<!-- coverage:restore -->
## Restore / Восстановление

`./restore.sh backups/it-tools-TIMESTAMP.tar.gz` проверяет архив и синтаксис Nginx до замены, делает страховочный backup и запускает сервер с восстановленным config. Используйте доверенный архив и соответствующую версию. Env/Compose автоматически не активируются: сравните их вручную. Браузерные данные не восстанавливаются.

<!-- coverage:update -->
## Update / Обновление

Изучите release notes, сохраните настройки, задайте явный тег и выполните `docker compose pull && docker compose up -d --wait`. Проверьте реальное преобразование в браузере. В текущем upstream нет новых стабильных релизов с 2024 года.

<!-- coverage:rollback -->
## Rollback / Откат

Верните сохранённый тег и проверенный config из backup. Сервера базы нет; браузерное хранилище новая версия может менять отдельно.

<!-- coverage:removal -->
## Removal / Удаление

`docker compose down` удаляет контейнер, сохраняя локальные config/env и браузерные данные. Удалите локальные файлы отдельно после backup; очистка сайта в браузере удаляет его предпочтения.

## Проверка

`./smoke-test.sh` использует Docker, Bash, curl, Python 3, Node >=22 и npm. Во временный каталог устанавливается Playwright 1.62.1 и Chromium; нужны системные библиотеки Chromium. Тест изменяет только собственную временную копию рецепта и удаляет её.
