## Требования и подготовка

Используйте 64-битную Ubuntu 22.04+ или Debian 12+ с Docker Engine и Compose v2.24+. Планируйте 2 ядра CPU, 4 ГБ RAM (рекомендуется 8 ГБ) и 10 ГБ диска плюс большие модели, данные пользователей и копии. Рецепт работает на CPU; GPU-устройства и Docker socket не монтируются.

```bash
mkdir -p ~/services/open-webui
cd ~/services/open-webui
# Скопируйте весь рецепт, скрипты и proxy/.
cp .env.example .env
chmod 600 .env
# Выполните дважды: секрет сервиса и независимый начальный пароль.
openssl rand -hex 32
openssl rand -hex 32
```

До запуска замените оба плейсхолдера. Все параметры `.env.example`:

| Параметр | Назначение |
| --- | --- |
| `OPEN_WEBUI_VERSION` | Точный тег приложения, изначально `v0.12.3`, с `v`. |
| `OLLAMA_VERSION` | Независимый точный тег сервера генерации, изначально `0.40.10`. |
| `OPEN_WEBUI_PORT` | Порт хоста на loopback, по умолчанию `3080`. |
| `OPEN_WEBUI_URL` | Точный origin браузера, изначально `http://localhost:3080`; за прокси укажите внешний HTTPS origin. Он используется и в CORS allowlist. |
| `OPEN_WEBUI_SECRET` | Случайный секрет сервиса; сохраняйте при восстановлении. |
| `OPEN_WEBUI_ADMIN_EMAIL` | Начальный логин администратора; замените `admin@example.com` своим адресом. |
| `OPEN_WEBUI_ADMIN_PASSWORD` | Независимый сложный начальный пароль; применяется только при отсутствии пользователей в БД. |
| `OPEN_WEBUI_TRUSTED_PROXIES` | Доверие Uvicorn к forwarded-заголовкам, изначально `127.0.0.1`. За прокси задайте его настоящий IP/CIDR, не `*`. Вход по заголовкам личности это не включает. |
| `OPEN_WEBUI_DATA_VOLUME` | SQLite, загрузки, локальные векторы/кеши и настройки. |
| `OLLAMA_DATA_VOLUME` | Веса локальных моделей и состояние Ollama. |
| `TZ` | Часовой пояс IANA, по умолчанию `Etc/UTC`. |
| `OPEN_WEBUI_BACKUP_DIR` | Необязательный абсолютный путь копий; по умолчанию `backups/` рядом с рецептом. |

Скрипты выполняют `.env` как доверенную shell-конфигурацию. Держите файл закрытым. Правка переменных первичного email/пароля не меняет существующий аккаунт. Часть настроек UI сохраняется в SQLite и может перекрывать начальные переменные окружения.

## Запуск и вход

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 600
curl --fail http://127.0.0.1:3080/health/db
```

Контейнер `permissions` завершится после назначения обоим томам UID/GID 1000; дальше оба сервера работают без root. Откройте `OPEN_WEBUI_URL` и войдите с заданными email и паролем администратора. С другого компьютера сначала используйте `ssh -L 3080:127.0.0.1:3080 user@server` и соответствующий локальный URL. Проверьте администратора и закрытую регистрацию до открытия прокси. Выберите язык и тему в личных настройках. Общего начального пароля нет.

## Скачивание и проверка модели

У запущенного Ollama сначала нет модели для чата. Скачайте её осознанно: нужны интернет и место на диске.

```bash
docker compose exec ollama ollama pull qwen3:0.6b
docker compose exec ollama ollama list
```

Обновите список моделей в Open WebUI, выберите `qwen3:0.6b` и отправьте короткое сообщение. Пример скачивает около 522 МБ и дополнительно занимает RAM при работе; модель мала и может отвечать плохо. У неё Apache-2.0; перед загрузкой другой модели проверьте её лицензию. Тег может меняться upstream, но копия сохраняет скачанные веса. Большие контексты и модели требуют больше RAM и диска. Держите Ollama внутри сети стека. `OFFLINE_MODE=true` предотвращает загрузки моделей/обновлений самим Open WebUI; образ содержит начальный кеш embeddings, а явное скачивание моделей Ollama остаётся доступным. Внешние провайдеры, GPU, плагины, голос и веб-поиск не настроены.

## VPS

<!-- coverage:deployment-vps -->

Укажите внешний HTTPS `OPEN_WEBUI_URL`, настройте прокси и оставьте в firewall только SSH/HTTP/HTTPS. Порт 3080 держите на loopback, Ollama — без порта на хосте. Используйте сложный пароль администратора и зашифрованные внешние копии. Недорогой CPU VPS может отвечать медленно; подбирайте сервер под модель, а не под веб-страницу.

## Доверенная локальная сеть

<!-- coverage:deployment-lan -->

Для личного доступа используйте SSH-туннель, для LAN — HTTPS-прокси. Если намеренно меняете привязку на приватный IP, ограничьте порт firewall и оставьте аутентификацию включённой. `OPEN_WEBUI_URL` должен совпадать с origin браузера: несовпадение может сломать websocket/CORS. Не выставляйте Ollama в LAN как API без аутентификации.

## Домен и HTTPS

<!-- coverage:deployment-domain-https -->

Используйте один пример из `proxy/`: Caddy получает сертификат, Nginx требует путей сертификатов, Traefik — `websecure` и resolver `letsencrypt`. Примеры работают на хосте и направляют запросы в `127.0.0.1:3080`. Контейнерному прокси нужны общая сеть и внутренний порт приложения 8080.

Задайте `OPEN_WEBUI_URL=https://chat.example.com` и реальный IP/CIDR прокси в `OPEN_WEBUI_TRUSTED_PROXIES`, затем выполните `docker compose up -d --wait --wait-timeout 600`. Прокси должен поддерживать websocket upgrades и долгие ответы генерации. Пример Nginx допускает запросы 100 МБ. Доверие forwarded-заголовкам отличается от входа по идентификационным заголовкам, который рецепт не включает. После изменений проверяйте сохранённые настройки UI.

## Резервное копирование

<!-- coverage:backup -->

```bash
./backup.sh
```

Скрипт останавливает оба процесса записи и сохраняет оба тома, `.env` и Compose в закрытый `backups/open-webui-<timestamp>.tar` с правами 600. Исходное состояние запуска/остановки каждого сервера сохраняется. Веса могут занимать много места, а копирование — прерывать текущие чаты. Шифруйте архив и переносите вне сервера: внутри переписки, файлы, модели, начальные реквизиты и секреты сервиса. Копия живого SQLite-файла и экспорт одного чата не заменяют полный архив.

## Восстановление

<!-- coverage:restore -->

**Восстановление заменяет оба тома.** Используйте доверенные архивы, соответствующие версии приложения/Ollama и исходный `OPEN_WEBUI_SECRET`. До восстановления сравните архивную `configuration.env` с рабочей `.env`: автоматически она не включается.

```bash
# На новом сервере сначала инициализируйте соответствующий рецепт.
docker compose up -d --wait --wait-timeout 600
./restore.sh ./backups/open-webui-TIMESTAMP.tar
curl --fail http://127.0.0.1:3080/health/db
```

Содержимое проверяется до замены, создаётся страховочная копия. Ошибка при замене файлов оставляет оба сервера остановленными. После восстановления войдите, откройте чат, скачайте файл и создайте новый ответ восстановленной моделью. Проверьте регистрацию, провайдеров и общий доступ. Smoke amd64 удаляет оба исходных тома и проверяет эти действия, включая digest модели и точные байты файла.

## Обновление

<!-- coverage:update -->

Прочитайте примечания upstream и совместимость моделей. Сделайте копию, перенесите вне сервера и измените проверенный точный тег в `.env`:

```bash
docker compose pull
docker compose up -d --wait --wait-timeout 600
docker compose logs --tail=100 open-webui ollama
```

Миграции приложения выполняются при запуске. У Ollama отдельная версия: читайте её примечания перед изменением. Не меняйте секрет сервиса без необходимости. Не используйте `latest`, не предполагайте совместимость API 0.x и не убирайте брендинг вне исключений лицензии.

## Откат

<!-- coverage:rollback -->

Не запускайте старое приложение на БД, мигрированной новой версией. Остановите оба сервера, укажите прежние точные теги и исходный секрет в `.env`, затем пересоздайте контейнеры без запуска:

```bash
docker compose stop open-webui ollama
# Измените обе проверенные версии и сохраните OPEN_WEBUI_SECRET.
docker compose pull open-webui ollama
docker compose create open-webui ollama
./restore.sh ./backups/open-webui-BEFORE-UPDATE.tar
```

Страховочная копия читает остановленные тома, не запуская старый код на новых данных. Восстановите полный соответствующий архив и проверьте чат, файл и локальную генерацию. Сохраняйте копию неудачной установки до подтверждения восстановления.

## Остановка и удаление

<!-- coverage:removal -->

`docker compose down` сохраняет оба тома. После проверки внешней копии `docker compose down --volumes` безвозвратно удаляет аккаунты, чаты, файлы, веса и состояние Ollama. Удаление каталога рецепта удаляет также локальные копии и `.env`.
