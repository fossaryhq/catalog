## Подготовка сервера

Используйте 64-битную Ubuntu 22.04+ или Debian 12+, Docker Engine и Compose v2.24+. Планируйте два ядра, минимум 2 ГБ RAM (рекомендуется 4 ГБ) и 10 ГБ диска плюс сохранённые материалы. Это ориентиры для планирования, а не результат нагрузочного теста.

```bash
mkdir -p ~/services/karakeep
cd ~/services/karakeep
# Скопируйте сюда все файлы рецепта, включая proxy/ и скрипты.
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
openssl rand -hex 32
```

Запишите два разных сгенерированных значения в `KARAKEEP_AUTH_SECRET` и `KARAKEEP_MEILI_KEY`. Скрипты подключают `.env` как доверенную конфигурацию shell. Используйте безопасные для shell значения и ограничьте доступ других пользователей.

| Параметр | Назначение |
| --- | --- |
| `KARAKEEP_VERSION` | Точный тег приложения, первоначально `0.34.1`, без `v`. |
| `KARAKEEP_PORT` | Порт хоста на loopback, по умолчанию `3000`. |
| `KARAKEEP_URL` | Точный origin браузера, первоначально `http://localhost:3000`; за прокси укажите внешний HTTPS-origin. Он также ограничивает доверенные origin аутентификации. |
| `KARAKEEP_AUTH_SECRET` | Случайный секрет сессий и входа; храните вместе с копией. |
| `KARAKEEP_MEILI_KEY` | Другой случайный ключ, общий для приложения и Meilisearch. |
| `KARAKEEP_DISABLE_SIGNUPS` | Обычно `true`; временно задайте `false` для первой регистрации через SSH-туннель. |
| `TZ` | Часовой пояс IANA, по умолчанию `Etc/UTC`. |
| `KARAKEEP_BACKUP_DIR` | Необязательный абсолютный каталог копий; пустое значение использует `backups/` рядом с рецептом. |

Именованный том `data` содержит SQLite, загрузки, сохранённые страницы и состояние очередей в `/data`. Том `search` хранит индекс Meilisearch в `/meili_data`. Состояние Chrome временное. Compose привязывает оба тома к проекту; сохраняйте имя проекта. Порты API поиска и DevTools браузера не публикуются.

## Запуск и создание учётной записи

Не включайте reverse proxy. Задайте `KARAKEEP_DISABLE_SIGNUPS=false`, затем:

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 600
curl --fail http://127.0.0.1:3000/api/health
```

На своём компьютере выполните `ssh -L 3000:127.0.0.1:3000 user@server`. Откройте `http://localhost:3000`, зарегистрируйтесь с уникальным паролем и проверьте вход. Задайте `KARAKEEP_DISABLE_SIGNUPS=true` и пересоздайте приложение:

```bash
docker compose up -d --wait --wait-timeout 600 karakeep
```

Публикуйте прокси только после закрытия регистрации. Готовых учётных данных в рецепте нет. Для дополнительных пользователей нужно ещё одно контролируемое окно регистрации. AI, SMTP и OIDC не настроены. Добавляйте внешний AI-ключ только после согласия с условиями обработки данных и оплаты.

## VPS

<!-- coverage:deployment-vps -->

Сначала создайте учётную запись через туннель. Задайте `KARAKEEP_URL=https://keep.example.com`, настройте DNS и HTTPS-прокси и пересоздайте Karakeep. Разрешите в firewall только SSH, HTTP и HTTPS. Оставьте порт 3000 на loopback и храните зашифрованные копии вне сервера.

## Доверенная локальная сеть

<!-- coverage:deployment-lan -->

Используйте SSH-туннель или HTTPS-прокси, доступный из доверенной LAN/VPN. Для прокси на хосте сохраняйте loopback-привязку. Если намеренно публикуете приватный интерфейс, ограничьте его firewall и задайте в `KARAKEEP_URL` точный origin пользователей. Не открывайте окно регистрации недоверенным пользователям.

## Домен и HTTPS

<!-- coverage:deployment-domain-https -->

Выберите пример в `proxy/`. Caddy получает сертификаты; Nginx нужны пути к сертификатам; Traefik — точка входа `websecure` и resolver `letsencrypt`. Эти примеры прокси на хосте направляют запросы на `127.0.0.1:3000`. Контейнерный прокси должен иметь общую сеть с Karakeep и использовать `karakeep:3000`; его loopback не является loopback хоста.

Замените домен и задайте в `KARAKEEP_URL` тот же внешний origin. Правильно передавайте `Host` и `X-Forwarded-Proto`; HTTPS-origin включает secure cookies. Пример Nginx допускает тело запроса до 50 МБ. Проверьте вход и загрузку по итоговому URL. Не публикуйте порты 7700 и 9222.

## Резервная копия

<!-- coverage:backup -->

```bash
./backup.sh
```

Скрипт останавливает Karakeep и Meilisearch, архивирует оба полных тома, активный `.env` и Compose, затем запускает только ранее работавшие сервисы. Приватный архив — `backups/karakeep-<timestamp>.tar`. SQLite и WAL нужно копировать вместе при остановленной записи. Храните индекс вместе с подходящей версией поискового движка.

Зашифруйте архив и скопируйте вне сервера. Он содержит учётные записи, приватные заметки, страницы, файлы, ключи и секреты. Личный экспорт и CLI-миграция между серверами не заменяют эту копию.

## Восстановление

<!-- coverage:restore -->

**Восстановление заменяет оба тома.** Используйте доверенный архив и совпадающие версии приложения и Meilisearch. На новом сервере скопируйте рецепт, изучите архивные `compose.yaml` и `configuration.env` и сначала создайте совместимую активную конфигурацию. Архивная конфигурация автоматически не активируется.

```bash
docker compose up -d --wait --wait-timeout 600
./restore.sh ./backups/karakeep-TIMESTAMP.tar
curl --fail http://127.0.0.1:3000/api/health
```

Скрипт проверяет состав архива, создаёт страховочную копию, заменяет тома и ждёт healthcheck. Если замена прервана, оставьте сервисы остановленными до восстановления проверенного архива. Войдите, прочитайте приватную заметку, откройте сохранённый файл и найдите известный материал. Smoke-тест проверяет учётную запись, приватную заметку и файл после удаления обоих исходных томов; он не доказывает восстановление между версиями.

## Обновление

<!-- coverage:update -->

1. Прочитайте [release notes](https://github.com/karakeep-app/karakeep/releases) и создайте копию вне сервера.
2. Измените `KARAKEEP_VERSION` на проверенную точную версию. Отдельно закреплённый образ Chrome меняйте после проверки его релиза и совместимости.
3. Выполните `docker compose pull`, затем `docker compose up -d --wait --wait-timeout 600`. Проверьте логи, вход, сохранённую страницу и поиск.
4. Смена версии Meilisearch — отдельная миграция. Следуйте [официальному руководству](https://github.com/karakeep-app/karakeep/blob/v0.34.1/docs/docs/06-administration/10-meilisearch-upgrade.md): полная копия, параметр миграции именно для выбранной версии движка, затем удаление этого параметра. Не запускайте новый движок на старых данных без миграции или осознанного пересоздания индекса.

Миграции приложения выполняются при запуске. Не используйте теги `latest` и `release`. Успешный healthcheck сам по себе не доказывает сохранность поиска и материалов.

## Откат

<!-- coverage:rollback -->

Не запускайте старое приложение на мигрировавшей SQLite или старый Meilisearch на новом индексе.

1. Сохраните архив до обновления и соответствующие рецепт и конфигурацию.
2. Остановите запись: `docker compose stop karakeep meilisearch`.
3. Верните точные старые версии приложения и вспомогательных образов в активных Compose и `.env`; сохраните подходящие секреты. Скачайте эти образы.
4. Выполните `docker compose create`, не запуская их на новых данных.
5. Выполните `./restore.sh ./backups/karakeep-BEFORE-UPDATE.tar`, затем проверьте вход, заметки, файлы и поиск. Страховочная копия умеет архивировать остановленные контейнеры без запуска старого приложения на новом состоянии.

## Остановка и удаление

<!-- coverage:removal -->

`docker compose down` сохраняет тома. После проверки зашифрованной внешней копии `docker compose down --volumes` навсегда удаляет библиотеку и индекс. Удаление каталога рецепта также удаляет локальную конфигурацию и копии. Не используйте глобальную очистку Docker.

Источники: [Docker](https://docs.karakeep.app/installation/docker), [настройка](https://docs.karakeep.app/configuration), [безопасность](https://docs.karakeep.app/administration/security-considerations), [ограничения миграции](https://docs.karakeep.app/administration/server-migration).
