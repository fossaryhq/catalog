Node-RED позволяет собирать автоматизацию как наглядный поток узлов. Входящий
webhook, таймер, MQTT-сообщение, HTTP-запрос, обращение к базе или небольшой
JavaScript-код передают данные следующему шагу. Среда особенно полезна для
устройств и умного дома, но подходит и как компактная собственная платформа для
API-связок и заданий по расписанию.

Рецепт запускает один официальный контейнер без отдельной базы данных. В
постоянном Docker-томе хранятся потоки, установленные узлы, настройки и
зашифрованные учётные данные. Редактор требует локально заданный пароль и по
умолчанию доступен только через localhost; перед публичным доступом используйте
один из примеров HTTPS reverse proxy.

Node-RED лучше n8n, когда нужен прямой контроль над событийными и IoT-потоками,
собственный JavaScript и небольшой runtime. У n8n больше готовых SaaS-коннекторов
и более подробная история запусков. В обоих случаях непроверенный community-узел
не становится безопасным — изучайте пакеты до установки.

### Оценка безопасности

Рецепт не использует privileged mode, host network или Docker socket и задаёт
`no-new-privileges`. Редактор по умолчанию привязан к `127.0.0.1`, поэтому не
доступен напрямую из сети.

Но сам редактор — высокопривилегированная панель управления. Любой, у кого есть
учётные данные редактора, может развернуть произвольный JavaScript в узлах
Function и установить сторонние palette-пакеты; и то и другое работает с
правами контейнера. Давайте доступ к редактору только тем, кому разрешён запуск
кода на сервере, и проверяйте community-узлы перед установкой.

Потоки могут содержать API-токены и пароли. Они шифруются
`NODE_RED_CREDENTIAL_SECRET`, но получивший одновременно этот секрет и
постоянный том или резервную копию сможет их расшифровать. Считайте `.env` и
резервные копии секретами уровня пароля. При публикации редактора или webhook
размещайте их за HTTPS, используйте отдельный стойкий пароль и не открывайте
порт 1880 напрямую.
