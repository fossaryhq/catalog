# Установка и обслуживание Tandoor

<!-- coverage:linux -->
## Ubuntu и Debian

Подойдут Ubuntu 24.04/26.04 LTS или Debian 12/13 с Docker Engine и Compose от v2.24, установленными по [инструкции Docker](https://docs.docker.com/engine/install/). Выполняйте команды из каталога рецепта. Установите `openssl`; Python 3 и curl нужны для smoke-теста. Доступ к Docker даёт административный контроль над хостом.

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 32  # TANDOOR_SECRET_KEY
openssl rand -hex 24  # TANDOOR_DB_PASSWORD
```

Вставьте разные сгенерированные значения в `.env`. Entrypoint веб-приложения отклоняет шаблонные секреты и ключ короче 50 символов до запуска HTTP. Пароль владельца создаётся в штатной форме настройки. Оставьте порт на loopback до создания владельца.

```bash
docker compose --env-file .env config --quiet
docker compose --env-file .env pull
docker compose --env-file .env up -d --wait --wait-timeout 600
docker compose ps --all
```

## VPS и первый владелец

Оставьте публичный прокси закрытым. Откройте туннель со своего компьютера:

```bash
ssh -L 8089:127.0.0.1:8089 user@server
```

Откройте `http://localhost:8089/setup/`, создайте владельца с уникальным паролем, затем используйте `http://localhost:8089/account/login/`. Настройка создаёт начальное пространство. Начальный email шаблонный; для подтверждения настоящего адреса и почтового сброса пароля сначала настройте SMTP. Обычная публичная регистрация выключена. Не возвращайтесь на `/setup/`: в upstream 2.7.2 после создания пользователя там есть ошибка перенаправления. До открытия HTTPS настройте firewall, обновления ОС и зашифрованные внешние копии.

<!-- coverage:deployment-lan -->
## Доверенная локальная сеть или VPN

Первую настройку выполните через туннель. Затем замените `127.0.0.1` в пробросе веб-порта на частный адрес сервера. Добавьте адрес в `TANDOOR_ALLOWED_HOSTS`, а в `TANDOOR_CSRF_TRUSTED_ORIGINS` укажите точный origin, например `http://192.168.1.10:8089`. Пересоздайте сервисы и разрешите доступ только доверенным клиентам или VPN. Обычный HTTP передаёт учётные и домашние данные без шифрования.

<!-- coverage:deployment-domain-https -->
## Домен и HTTPS

Направьте `recipes.example.com` на сервер. Оставьте приложение на loopback, задайте `TANDOOR_ALLOWED_HOSTS=localhost,127.0.0.1,recipes.example.com` и `TANDOOR_CSRF_TRUSTED_ORIGINS=https://recipes.example.com`, затем выполните `docker compose up -d --wait --wait-timeout 600`. Передавайте исходный Host и `X-Forwarded-Proto`. Tandoor доверяет заголовку протокола, поэтому не допускайте недоверенный прямой доступ к backend. Оставляйте remote-user выключенным, если нет доверенного аутентифицирующего прокси, удаляющего подставленные клиентом заголовки личности.

## Caddy, Nginx и Traefik

`proxy/Caddyfile` получает HTTPS-сертификат и направляет домен на loopback. Для `proxy/nginx.conf` укажите пути сертификатов; до перезагрузки выполните `nginx -t`. `proxy/traefik.yaml` — динамическая конфигурация file provider для существующего Traefik с его certificate resolver. Примеры предполагают прокси на Docker-хосте. Контейнерному прокси нужна контролируемая общая сеть или доступный адрес хоста: его loopback указывает на него самого. Отдельный прокси статики и медиа не нужен: официальный образ уже включает Nginx.

## Данные и все параметры

Создаются три тома проекта: `database` в `/var/lib/postgresql`, `media` в `/opt/recipes/mediafiles` и `static` в `/opt/recipes/staticfiles`. PostgreSQL хранит рецепты, пользователей, пространства, меню, покупки и настройки интеграций. Изображения и пользовательские файлы находятся в media. Статика создаётся при каждом запуске и не является пользовательскими данными. Инициализатор назначает корням media/static UID/GID 65534; приложение работает без root. Не меняйте UID и владельцев томов вслепую.

| Переменная | Назначение |
| --- | --- |
| `TANDOOR_VERSION` | Закреплённая версия приложения `2.7.2`. |
| `TANDOOR_PORT` | Веб-порт loopback, `8089`. |
| `TANDOOR_SECRET_KEY` | Случайный Django-секрет от 50 символов; храните вместе с архивами. |
| `TANDOOR_DB_PASSWORD` | Уникальный пароль PostgreSQL, заданный до первого запуска; правка только `.env` не меняет пароль существующей роли БД. |
| `TANDOOR_ALLOWED_HOSTS` | Имена и IP через запятую, без схем и портов; сохраняйте loopback для healthcheck. |
| `TANDOOR_CSRF_TRUSTED_ORIGINS` | Точные origin через запятую, со схемой и нестандартным портом, без wildcard. |
| `TZ` | IANA-часовой пояс приложения, стандартно `UTC`. |

Скрипты также принимают `FOSSARY_ENV_FILE`, `COMPOSE_PROJECT_NAME` и `TANDOOR_BACKUP_DIR`, по умолчанию `.env`, проект `tandoor` и `backups/`. Если запускали `docker compose -p` с другим именем, экспортируйте тот же `COMPOSE_PROJECT_NAME` для резервирования и восстановления. SMTP, AI, внешние хранилища и провайдеры личности не настроены; рецепт не требует их ключей.

<!-- coverage:backup -->
## Резервирование

```bash
bash backup.sh
```

Дождитесь окончания инициализации. Скрипт останавливает приложение, делает дамп PostgreSQL и сохраняет полный том media, `.env` и Compose. Приложение запускается обратно только если работало до копирования. Архивы имеют приватные права и уникальные имена; шифруйте внешнюю копию и репетируйте восстановление. Экспорт рецептов не сохраняет аккаунты, меню, покупки и все настройки. Статика пересоздаётся и в архив не входит.

<!-- coverage:restore -->
## Восстановление — заменяет текущие данные

Используйте доверенные архивы и совпадающие версии приложения, базы и секреты. На новой машине подготовьте конфигурацию без запуска приложения:

```bash
docker compose up -d --wait database
docker compose create --no-deps tandoor initialize
bash restore.sh /absolute/path/tandoor-<timestamp>.tar
```

Восстановление проверяет состав архива, делает страховочную копию, останавливает запись, пересоздаёт базу приложения, заменяет media и ждёт healthcheck. Архивный `.env` автоматически не активируется. Проверьте вход, инструкции рецептов, фотографии, меню и покупки до открытия доступа. При сбое оставьте запись остановленной и изучите журналы до новой попытки. Для другой машины также исправьте параметры host/origin.

## Обновление

Прочитайте [release notes](https://github.com/TandoorRecipes/recipes/releases) и [описание параметров](https://docs.tandoor.dev/system/configuration/). Сохраните старые `.env`, Compose и проверенный архив, остановите приложение, выберите изученный закреплённый `TANDOOR_VERSION` и перезапустите:

```bash
bash backup.sh
docker compose stop tandoor
# Измените TANDOOR_VERSION в .env; сохраняйте мажорную версию PostgreSQL.
docker compose pull tandoor
docker compose up -d --wait --wait-timeout 600
docker compose logs --tail=100 tandoor
```

При запуске мигрирует PostgreSQL и пересоздаётся статика. Проверьте рецепты, медиа, права, меню и покупки. Для мажорного обновления PostgreSQL нужен отдельный план экспорта и импорта; не используйте каталог данных с другой мажорной версией образа.

<!-- coverage:rollback -->
## Откат

1. Закройте внешний доступ и остановите `tandoor`.
2. Верните предыдущие `.env` и Compose, сохраняя совпадающий секрет и мажорную версию базы; укажите старый `TANDOOR_VERSION`.
3. Загрузите прежний образ, запустите только БД и выполните `docker compose create --no-deps tandoor initialize`. Не запускайте старое приложение поверх новой схемы.
4. Выполните `bash restore.sh /path/to/pre-upgrade.tar`. Страховочная копия сохранит текущее состояние до замены старой базой и media; статика пересоздастся.
5. Проверьте вход, рецепты, фотографии, меню и покупки до открытия прокси. Одна смена образа не отменяет миграции.

<!-- coverage:removal -->
## Остановка и удаление

`docker compose down` сохраняет тома. После проверки внешней копии `docker compose down --volumes --remove-orphans` уничтожает базу, все загрузки и статику. `.env` и локальные архивы удаляйте отдельно, когда они больше не нужны.
