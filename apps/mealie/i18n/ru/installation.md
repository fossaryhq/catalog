## Требования

Нужен 64-разрядный сервер Ubuntu 22.04+ или Debian 12+ с Docker Engine и Compose v2.24+. Официальный образ поддерживает amd64 и arm64; 32-разрядный ARM не поддерживается. Минимальный ориентир — 1 CPU, 1 ГБ RAM и 5 ГБ свободного места для приложения и изображений. Загружаемые фотографии потребуют дополнительного диска.

## Подготовка

```bash
mkdir -p ~/services/mealie
cd ~/services/mealie
# Скопируйте сюда compose.yaml, .env.example, backup.sh, restore.sh и proxy/.
cp .env.example .env
chmod 600 .env
```

До первого запуска измените `.env`:

- `MEALIE_VERSION` — закреплённая версия upstream. Перед обновлением читайте примечания к выпуску.
- `MEALIE_PORT` — порт на хосте, по умолчанию `9925`; Compose привязывает его к `127.0.0.1`.
- `MEALIE_BASE_URL` — адрес для ссылок и callback. При домене укажите публичный HTTPS URL.
- `PUID` и `PGID` задают ID владельца файлов в томе данных.
- `TZ` задаёт часовой пояс.
- `MEALIE_DEFAULT_LOCALE` задаёт начальный язык интерфейса: `en` или `ru`.
- `MEALIE_DATA_VOLUME` — имя тома с базой SQLite, изображениями рецептов и другими данными.

## Запуск и вход

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 300
docker compose ps
curl --fail http://127.0.0.1:9925/api/app/about
```

Откройте на сервере `http://127.0.0.1:9925` и войдите в начальную учётную запись (`changeme@example.com` / `MyPassword`). Сразу смените опубликованный пароль по умолчанию в настройках учётной записи, до предоставления доступа другим. Регистрация в этом рецепте отключена. Приглашайте участников домохозяйства через Mealie, не включая открытую регистрацию.

## VPS

<!-- coverage:deployment-vps -->

Оставьте порт хоста на loopback. Направьте домен на сервер, настройте один из HTTPS-прокси ниже, разрешите в firewall SSH/HTTP/HTTPS и не открывайте наружу порт 9925. Сначала войдите локально и замените опубликованный начальный пароль, лишь затем открывайте домен. До первого запуска задайте `MEALIE_BASE_URL=https://recipes.example.com`, чтобы ссылки и callback авторизации использовали правильный адрес. Импорт рецептов требует исходящего доступа в интернет.

## Доступ из доверенной локальной сети

<!-- coverage:deployment-lan -->

Для временного доступа используйте SSH-туннель:

```bash
ssh -L 9925:127.0.0.1:9925 user@server
```

Затем откройте `http://localhost:9925`. Чтобы дать доступ в локальной сети, поместите Mealie за доверенным HTTPS-прокси либо измените привязку порта на конкретный приватный IP и ограничьте её firewall. Не публикуйте приложение напрямую в интернете по обычному HTTP.

## Домен и HTTPS

<!-- coverage:deployment-domain-https -->

Укажите `MEALIE_BASE_URL=https://recipes.example.com`, направьте DNS на прокси и используйте подходящий пример Caddy, Nginx или Traefik из `proxy/`. Оставьте соединение до приложения на loopback. Конфигурация Nginx разрешает загрузки до 20 МБ; увеличивайте предел осознанно, если нужны фотографии большего размера.

## Резервная копия

<!-- coverage:backup -->

В постоянном томе находятся база и загруженные файлы. Остановите Mealie, чтобы SQLite и файлы попали в согласованный снимок:

```bash
./backup.sh
```

Архив появится в `backups/` рядом с рецептами. В нём могут находиться личные рецепты и данные домохозяйства. Защитите его как персональные данные и скопируйте за пределы сервера. Файл `.env` тоже сохраните отдельно в защищённом месте: начальные данные администратора и публичный адрес нужны для работы восстановленного экземпляра.

## Восстановление

<!-- coverage:restore -->

Восстановление заменяет текущий том данных. Перед этим скрипт создаёт страховочную копию текущего состояния:

```bash
./restore.sh ./backups/mealie-YYYYMMDDTHHMMSSZ.tar.gz
```

Проверьте сервис и войдите:

```bash
docker compose up -d --wait --wait-timeout 300
curl --fail http://127.0.0.1:9925/api/app/about
docker compose logs --tail=100 mealie
```

Smoke-тест проверяет этот сценарий backup и restore на amd64. Для архива нужны совместимая версия образа и файл `.env`.

## Обновление

<!-- coverage:update -->

Прочитайте примечания Mealie к выпуску и сохраните копию за пределами сервера. Укажите в `.env` точную проверенную версию `MEALIE_VERSION`, затем выполните:

```bash
./backup.sh
docker compose pull
docker compose up -d --wait --wait-timeout 300
docker compose logs --tail=100 mealie
```

Не используйте `latest`. Миграция базы проходит при запуске; дождитесь успешного healthcheck.

## Откат

<!-- coverage:rollback -->

Не запускайте старую версию на данных, которые уже мигрировала новая. Верните в `MEALIE_VERSION` предыдущий тег и восстановите архив, созданный до обновления:

```bash
docker compose down
./restore.sh ./backups/mealie-BEFORE-UPDATE.tar.gz
docker compose up -d --wait --wait-timeout 300
```

## Остановка и удаление

<!-- coverage:removal -->

Остановить сервис, сохранив данные:

```bash
docker compose down
```

Чтобы удалить приложение вместе с данными, сначала проверьте резервную копию вне сервера, затем выполните:

```bash
docker compose down --volumes
rm -rf ~/services/mealie
```

Это удалит рецепты, учётные записи, планы питания, списки покупок и загруженные изображения.

## Безопасность

Функция импорта по ссылке выполняет исходящие запросы с сервера. Давайте доступ только доверенным пользователям и по возможности изолируйте приложение от важных внутренних сервисов. У начальной учётной записи пароль опубликован в документации upstream; смените его до доступа извне loopback. Отключённая регистрация не заменяет отдельные учётные записи: приглашайте членов домохозяйства и задавайте уникальные пароли. Значение Mealie `HOST_IP=*` по умолчанию доверяет пересылаемым заголовкам от любого источника. При использовании прокси ограничьте его IP-адресом или сетью прокси и закройте прямой доступ к приложению.
