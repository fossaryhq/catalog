## Ubuntu и Debian
Подойдут Ubuntu 24.04 LTS или Debian 12/13, Docker Engine и Docker Compose >=2.24.0. Установите Docker из [официального репозитория](https://docs.docker.com/engine/install/) вместе с Compose plugin. Скачайте рецепт целиком, включая `config/`.

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 24
openssl rand -hex 32
```

Первое случайное значение впишите в `HOMEPAGE_AUTH_PASSWORD`, второе — в `HOMEPAGE_AUTH_SECRET`. Замените значения CHANGE_ME; пустые значения недопустимы. Укажите URL и разрешённые Host, затем запустите:

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait
docker compose ps
```

Откройте `http://localhost:3000`, введите пароль и настройте YAML в `config/`. Инициализатор меняет владельца на UID/GID 1000; при необходимости редактируйте через sudo. После изменений перезапускайте `homepage`. Все вошедшие посетители видят общую конфигурацию.

<!-- coverage:deployment-vps -->
## VPS
Нужны домен, HTTPS, firewall и зашифрованные внешние backup. Оставьте порт 3000 на loopback, наружу выставляйте только прокси. Закройте вход VPN/списком IP либо настройте ограничение попыток на внешнем прокси: встроенного лимита нет. Пример Nginx включает ограничение; для Caddy и Traefik его нужно организовать отдельно.

<!-- coverage:deployment-lan -->
## Доверенная LAN или VPN
По умолчанию доступ только через loopback. Предпочтительны SSH-туннель (`ssh -L 3000:127.0.0.1:3000 user@server`) или VPN/прокси. Для прямой LAN явно поменяйте опубликованный адрес Compose и ограничьте доступ firewall. В `HOMEPAGE_EXTERNAL_URL` укажите точный адрес браузера, в `HOMEPAGE_ALLOWED_HOSTS` — его host:port. Не используйте `*`.

<!-- coverage:deployment-domain-https -->
## Домен и HTTPS
Для `https://home.example.com` задайте `HOMEPAGE_EXTERNAL_URL=https://home.example.com` и `HOMEPAGE_ALLOWED_HOSTS=home.example.com`, затем пересоздайте сервис. URL определяет защищённые cookies сессии и должен совпадать с реальным адресом браузера.

<!-- coverage:proxy-caddy -->
### Caddy
Подключите `proxy/Caddyfile` на хосте после настройки DNS. Caddy получает TLS автоматически. Добавьте VPN/ограничение IP или отдельно настроенный лимит попыток входа.

<!-- coverage:proxy-nginx -->
### Nginx
Используйте `proxy/nginx.conf`, предварительно получите сертификаты и проверьте `sudo nginx -t`. `limit_req_zone` располагается в контексте `http`. Обработчик пароля ограничен пятью запросами в минуту с burst пять; подберите значения для своих пользователей и наблюдения.

<!-- coverage:proxy-traefik -->
### Traefik
Загрузите `proxy/traefik.yaml` через file provider с entry point `websecure` и resolver `letsencrypt`. Пример предполагает Traefik на хосте; контейнер не видит loopback хоста без подходящей сети. Добавьте VPN/ограничение IP либо защиту входа на внешнем прокси.

## Данные и окружение
`HOMEPAGE_CONFIG_DIR` (по умолчанию `./config`) подключён к `/app/config`: настройки, сервисы, закладки, виджеты, custom-файлы и логи. При переносе рецепта используйте абсолютный путь и не делите его с другим приложением. Базы данных нет. Сохраняйте пользовательские иконки внутри этого каталога, если они нужны конфигурации.

Все параметры `.env.example`:

| Переменная | Значение |
| --- | --- |
| `HOMEPAGE_VERSION` | Фиксированный тег образа, исходно `v2.7.0` |
| `HOMEPAGE_PORT` | HTTP-порт loopback хоста, исходно `3000` |
| `HOMEPAGE_CONFIG_DIR` | Каталог конфигурации; инициализатор задаёт владельца 1000:1000 |
| `HOMEPAGE_ALLOWED_HOSTS` | Точные Host через запятую, с нестандартными портами |
| `HOMEPAGE_EXTERNAL_URL` | Адрес браузера со схемой и при необходимости портом |
| `HOMEPAGE_AUTH_PASSWORD` | Обязательный сложный общий пароль панели |
| `HOMEPAGE_AUTH_SECRET` | Обязательный случайный секрет сессий от 32 символов |
| `TZ` | Часовой пояс, исходно `Etc/UTC` |
| `HOMEPAGE_BACKUP_DIR` | Необязательная закрытая папка для `backup.sh` |

Для смены пароля или секрета поправьте `.env` и пересоздайте сервис. Не помещайте секреты в custom CSS/JavaScript и статику: они публичны. Ключам виджетов выдавайте минимум прав. Docker/Kubernetes discovery и OIDC в рецепте не включены.

<!-- coverage:backup -->
## Резервная копия

```bash
bash backup.sh
```

Скрипт останавливает запись, сохраняет весь каталог конфигурации, `.env` и Compose, затем возвращает прежнее состояние запуска. Права архивов — 600. Копируйте их за пределы сервера и шифруйте: внутри могут быть API-ключи и секреты входа. Временный кеш образа и local storage браузера не входят в backup. Внешние пользовательские ресурсы вне config сохраняйте отдельно.

<!-- coverage:restore -->
## Восстановление
Восстановление заменяет всю конфигурацию. Используйте только собственный доверенный архив. Один раз запустите рецепт для создания контейнера и mount, вручную сравните архивную `configuration.env` с текущей `.env` и согласуйте версию. Архивное окружение не исполняется и не активируется автоматически.

```bash
bash restore.sh /safe/path/homepage-backup.tar
```

Скрипт проверяет обязательные файлы до остановки, делает страховочный backup, заменяет каталог конфигурации и ждёт health. При ошибке распаковки сервис остаётся остановлен. Войдите и проверьте ссылки и закладки. Возврат старого секрета может снова разрешить ещё действующие старые cookies; при необходимости смените секрет.

<!-- coverage:update -->
## Обновление
Прочтите release notes, сделайте backup, установите новый явный `HOMEPAGE_VERSION` и выполните `docker compose pull && docker compose up -d --wait`. Не используйте `latest`. Проверьте вход и каждую интеграцию. Для текущего рецепта это замена образа на месте; перед будущими major-релизами изучайте отдельные инструкции.

<!-- coverage:rollback -->
## Откат
Остановите `homepage`, верните прежний фиксированный тег в `.env`, скачайте и один раз запустите его, затем восстановите соответствующий архив до обновления через `restore.sh`. Сверьте окружение и проверьте вход/виджеты. Миграций БД в рецепте нет, но новые параметры YAML могут не поддерживаться старым образом: возвращайте соответствующую конфигурацию.

<!-- coverage:removal -->
## Остановка и удаление
`docker compose down` удаляет контейнеры и сети, сохраняя bind-каталог. Для полного удаления сначала выгрузите backup, выполните `docker compose down --volumes` и отдельно удалите только выбранный `HOMEPAGE_CONFIG_DIR` и закрытую `.env`, проверив абсолютные пути. Это уничтожит настройки и ключи внутри. DNS, прокси и ненужные backup удаляются отдельно.

[Официальное руководство по доступу](https://gethomepage.dev/installation/) описывает пароль/OIDC, публичную статику, проверку Host и отсутствие встроенного лимита входа.
