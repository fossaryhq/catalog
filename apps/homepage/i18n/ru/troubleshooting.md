## Диагностика

```bash
docker compose ps
docker compose logs --tail=100 homepage
docker compose config --quiet
curl -fsS http://127.0.0.1:3000/api/healthcheck
```

**Host validation failed:** разрешите точный адрес браузера с портом в `HOMEPAGE_ALLOWED_HOSTS`. Не ставьте wildcard. Health с внутренним Host 127.0.0.1:3000 не доказывает доступность внешнего адреса.

**Вход зацикливается или cookie не сохраняется:** `HOMEPAGE_EXTERNAL_URL` должен совпадать со схемой и адресом браузера. Для HTTPS cookie защищённая и не работает через HTTP. После изменения `.env` пересоздайте контейнер.

**Ошибка YAML или нет ссылок:** проверяйте отступы в settings/services/bookmarks/widgets. Закладки содержат дополнительный список с `href`, сервисы — объект. Перезапустите приложение. Неверная конфигурация может сломать панель даже при успешном health.

**Permission denied:** каталог config и logs должны быть доступны UID/GID 1000. Инициализатор меняет владельца рекурсивно; не указывайте системную или чужую папку. При NFS/root-squash настройте права на стороне хранилища.

**Виджет не работает:** URL должен быть доступен из контейнера; localhost указывает на сам Homepage. Проверьте минимальные права токена. Рецепт не подключает Docker socket и Kubernetes и не устанавливает связанные приложения.

**Слишком много попыток входа:** ограничивайте обработчик пароля на прокси или используйте VPN/IP. В логах есть `Failed password sign-in attempt`; не публикуйте дампы конфигурации с секретами.

**Backup/restore:** запускайте из полного рецепта с его `.env`; для другого env используйте `FOSSARY_ENV_FILE`. Архив сохраняет секреты. При неудачной распаковке сервис остаётся остановлен: проверьте логи, свободное место, права и страховочный архив перед повтором. На чистой машине сначала запустите рецепт один раз.
