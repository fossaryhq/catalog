## Требования и подготовка

Используйте 64-битную Ubuntu 22.04+ или Debian 12+ с Docker Engine и Compose v2.24+. Планируйте одно ядро CPU, 256 МБ RAM (рекомендуется 512 МБ) и 1 ГБ диска плюс заметки и вложения.

```bash
mkdir -p ~/services/memos
cd ~/services/memos
# Скопируйте сюда весь рецепт, включая config/, proxy/ и скрипты.
cp .env.example .env
chmod 600 .env
# В двух файлах политик нет секретов; UID 10001 должен их читать.
chmod 755 config
chmod 644 config/memos-instance-setting-*.json
```

| Параметр | Назначение |
| --- | --- |
| `MEMOS_VERSION` | Точный Docker-тег, изначально `0.31.0`, без `v`. |
| `MEMOS_PORT` | Порт хоста на loopback, по умолчанию `5230`. |
| `MEMOS_URL` | Канонический адрес браузера, изначально `http://localhost:5230`; за прокси укажите внешний HTTPS URL. |
| `MEMOS_TRUSTED_PROXIES` | `none` для прямого доступа. Для HTTPS-прокси, перезаписывающего заголовки, укажите его IP/CIDR; `private` допустим только при доверии всем доступным приватным посредникам. |
| `MEMOS_DATA_VOLUME` | Именованный том SQLite, локальных файлов и постоянных секретов инстанса. |
| `TZ` | Часовой пояс IANA, по умолчанию `Etc/UTC`. |
| `MEMOS_BACKUP_DIR` | Необязательный абсолютный путь копий; по умолчанию `backups/` рядом с рецептом. |

Скрипты выполняют `.env` как доверенную shell-конфигурацию. Держите файл закрытым. В `config/` два параметра развёртывания: GENERAL закрывает регистрацию, ACCESS задаёт приватный доступ. Они перекрывают настройки БД/UI и применяются после перезапуска контейнера. Храните каталог с рецептом.

## Запуск и создание администратора

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 300
curl --fail http://127.0.0.1:5230/healthz
```

С другого компьютера сначала выполните `ssh -L 5230:127.0.0.1:5230 user@server`. Откройте `http://localhost:5230`, создайте первый аккаунт с уникальным паролем **до открытия прокси**. Первый аккаунт становится администратором; общего начального пароля нет. Публичная регистрация затем остаётся закрытой. Следующих пользователей добавляйте в настройках администратора. Язык и тему выберите в настройках аккаунта.

Штатный entrypoint исправляет владельца тома и переходит на UID/GID 10001. Корневая ФС доступна только для чтения; том данных и `/tmp` доступны для записи. SMTP, SSO, AI-провайдеры, внешние хранилища и вебхуки не настроены.

## VPS

<!-- coverage:deployment-vps -->

Сначала создайте администратора через туннель. Укажите `MEMOS_URL=https://notes.example.com`, настройте HTTPS-прокси и оставьте в firewall только SSH/HTTP/HTTPS. Порт 5230 сохраняйте на loopback. Шифруйте копии и храните экземпляр вне сервера.

## Доверенная локальная сеть

<!-- coverage:deployment-lan -->

Для личного доступа используйте SSH-туннель. Для общего доступа в LAN настройте HTTPS-прокси. Если меняете привязку на приватный IP, ограничьте порт firewall и оставьте `MEMOS_TRUSTED_PROXIES=none`, пока в цепочке нет доверенного прокси, перезаписывающего заголовки. Канонический URL должен совпадать с адресом пользователей.

## Домен и HTTPS

<!-- coverage:deployment-domain-https -->

Используйте один пример из `proxy/`: Caddy получает сертификат, Nginx требует путей сертификатов, Traefik — entry point `websecure` и resolver `letsencrypt`. Примеры работают на хосте и передают запросы в `127.0.0.1:5230`; контейнерному прокси нужны общая сеть и внутренний порт 5230.

Укажите внешний `MEMOS_URL`. Доверяйте только IP/CIDR прокси; `private` доверяет также loopback и приватным диапазонам, поэтому применяйте его лишь с loopback-привязкой и прокси, перезаписывающим forwarded-заголовки. Выполните `docker compose up -d --wait --wait-timeout 300`. Nginx разрешает запросы до 50 МБ, но у Memos отдельно действует лимит загрузки 30 МБ по умолчанию.

## Резервное копирование

<!-- coverage:backup -->

```bash
./backup.sh
```

Запись останавливается на время архивации всего тома, рабочей `.env`, Compose и `config/`. Закрытый архив один: `backups/memos-<timestamp>.tar`. Работавшее приложение запускается снова; остановленное остаётся остановленным. Зашифруйте архив и перенесите вне сервера: внутри аккаунты, заметки, вложения и секреты инстанса/сессий. Копия одного живого SQLite-файла и личный экспорт не заменяют этот архив.

## Восстановление

<!-- coverage:restore -->

**Восстановление заменяет весь том приложения.** Используйте доверенные архивы и совпадающую версию. На новом сервере скопируйте рецепт и сначала сравните архивные `configuration.env` и `config.tar.gz` с рабочими `.env` и `config/`. Архивная конфигурация автоматически не включается.

```bash
docker compose up -d --wait --wait-timeout 300
./restore.sh ./backups/memos-TIMESTAMP.tar
curl --fail http://127.0.0.1:5230/healthz
```

Скрипт проверяет содержимое до замены и делает страховочную копию. Ошибка при замене оставляет приложение остановленным. После восстановления войдите, откройте приватную заметку и скачайте вложение. Smoke-тест amd64 удаляет исходный том перед восстановлением и проверяет эти действия.

## Обновление

<!-- coverage:update -->

Прочитайте примечания, сделайте копию и перенесите её вне сервера. Задайте проверенный точный тег `MEMOS_VERSION`, затем:

```bash
docker compose pull
docker compose up -d --wait --wait-timeout 300
docker compose logs --tail=100 memos
```

Миграции выполняются при запуске. API 0.x может меняться между минорными версиями: проверьте совместимость клиентов и интеграций. Версия 0.31 убирает RSS и расширяет доступ администратора. Не используйте `latest` и не считайте старый клиент совместимым с новым API без проверки.

## Откат

<!-- coverage:rollback -->

Не запускайте старый образ на мигрированной БД. Сохраните копию до обновления, остановите приложение, задайте старую точную версию в `.env`, скачайте и пересоздайте контейнер без запуска:

```bash
docker compose stop memos
# Измените MEMOS_VERSION и сравните соответствующий config/.
docker compose pull memos
docker compose create memos
./restore.sh ./backups/memos-BEFORE-UPDATE.tar
```

Страховочная копия читает том остановленного контейнера, не запуская старую версию на новых данных. Восстановите целый соответствующий архив, затем проверьте вход, заметку и файл.

## Остановка и удаление

<!-- coverage:removal -->

`docker compose down` удаляет контейнеры и сохраняет том. После проверки зашифрованной внешней копии `docker compose down --volumes` безвозвратно удаляет аккаунты, заметки и вложения. Удаление каталога рецепта удаляет также локальные копии и конфигурацию.
