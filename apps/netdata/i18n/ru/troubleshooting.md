# Ошибки Netdata

<!-- coverage:troubleshooting -->
Начните с `docker compose ps` и `docker compose logs --tail 100 netdata gateway`. Всегда используйте один и тот же каталог проекта и `.env`. Не публикуйте пароли, API-ключи или полные архивы в issue.

## Шлюз не запускается

Замените шаблон bcrypt-хешем из `caddy hash-password`. В `.env` сохраните одинарные кавычки вокруг хеша: знаки доллара не должны интерполироваться. `config/Caddyfile` должен читаться с правами 644. Официальный бинарник Caddy содержит file capability; рецепт сохраняет `NET_BIND_SERVICE` даже для порта 8080. Без неё запуск бинарника может завершиться «Operation not permitted».

## 401, в том числе через HTTPS

Используйте имя пользователя из `.env` и исходный пароль, а не хеш. Для смены пароля замените хеш и пересоздайте `gateway`. Внешний прокси должен сохранять Authorization. Не исправляйте 401 обходом шлюза или публикацией порта агента.

## Порт не опубликован

Шлюзу нужна frontend bridge-сеть вместе с приватной сетью агента. На некоторых версиях Docker одна internal-сеть не публикует рабочий порт хоста. Сохраните обе сети шлюза; агент остаётся в приватной.

## Панель медленно загружается или не достигает network-idle

UI делает live-запросы и может обращаться к доменам Netdata. Ждите появления графиков, а не сетевого простоя. Для встроенного интерфейса открывайте `/v3/`. Браузерные ресурсы и телеметрия агента — разные механизмы. Кнопка входа в Cloud не означает, что для локального сбора требуется облачная учётная запись. Раздел Live с таблицами функций современного UI требует подключённого агента и входа в Cloud.

## Нет метрик процессов, устройств или контейнеров

См. [официальную таблицу прав](https://github.com/netdata/netdata/blob/v2.12.2/packaging/docker/README.md). Рецепт не предоставляет дополнительные SYS_ADMIN/SYS_PTRACE, unconfined-профиль, host networking или Docker socket. Предупреждения о доступе к части дескрипторов процессов ожидаемы. Под Docker Desktop мониторится Linux-VM. Некоторые новые монтирования хоста видны только после перезапуска агента. Полный доступ к физическому оборудованию и метки всех контейнеров не проверены.

## Неверные сведения о хосте

Проверьте `NETDATA_HOSTNAME` и авторизованный `/api/v1/info`. Сравнивайте число CPU с примонтированным `/proc` хоста, а не только с ограничениями контейнера. Корень, `/proc`, `/sys` и OS-release должны относиться к одному Docker-хосту. Удалённый Docker daemon разрешает bind-пути на своей машине, а не на клиентском ноутбуке.

## Архив отклонён или пропала история

Сохраните исходный архив неизменным. Нужны оба архива томов и справочная конфигурация. Абсолютные пути, обход каталогов и ссылки внутри архивов метрик отклоняются. Отказ проверки не должен затрагивать работающую установку. Проверьте свободный диск и совпадение закреплённых версий; восстановление одного `/var/lib/netdata` не вернёт историю dbengine из `/var/cache/netdata`.

## Находки сканера безопасности

Зафиксированы восемь CRITICAL-находок в пакетах закреплённых образов Agent и шлюза. Некоторые CVE повторяются для разных пакетов. Следите за исправлениями upstream и пересканируйте проверенные образы; успешный запуск или восстановление не означают устранения находок.
