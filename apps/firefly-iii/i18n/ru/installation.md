# Установка и обслуживание Firefly III

<!-- coverage:linux -->
## Ubuntu и Debian

Подойдут Ubuntu 24.04/26.04 LTS или Debian 12/13 с Docker Engine и Docker Compose от v2.24; установите их по [инструкции Docker](https://docs.docker.com/engine/install/). Команды выполняются из каталога рецепта. Установите `openssl`; Python 3 и curl нужны только для smoke-теста. Доступ к Docker даёт административный контроль над хостом.

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 16  # FIREFLY_APP_KEY: ровно 32 символа
openssl rand -hex 16  # FIREFLY_CRON_TOKEN: ровно 32 символа
openssl rand -hex 24  # FIREFLY_DB_PASSWORD
```

Вставьте три разных результата в `.env`, задайте `FIREFLY_SITE_OWNER` и оставьте привязку к loopback до первой регистрации. Entrypoint отклоняет шаблонный ключ, шаблонный пароль БД и неверную длину ключа или токена до запуска HTTP. Пароль администратора создаётся в браузере, а не в `.env`.

```bash
docker compose --env-file .env config --quiet
docker compose --env-file .env pull
docker compose --env-file .env up -d --wait --wait-timeout 600
docker compose ps
```

## VPS и первый владелец

Создайте владельца **до** публикации через прокси. Для удалённого сервера откройте туннель со своего компьютера:

```bash
ssh -L 8088:127.0.0.1:8088 user@server
```

Откройте `http://localhost:8088`, зарегистрируйтесь с уникальным паролем от 16 символов и завершите настройку счетов и валюты. Стандартный однопользовательский режим закрывает регистрацию после первого аккаунта. Включите TOTP в профиле и сохраните коды восстановления отдельно. Затем открывайте публичный HTTPS. Не публикуйте порты PostgreSQL и cron; настройте firewall, обновления и зашифрованные внешние копии.

<!-- coverage:deployment-lan -->
## Доверенная локальная сеть или VPN

Для первого входа используйте тот же туннель. После регистрации замените `127.0.0.1` в пробросе веб-порта на частный адрес сервера, задайте `FIREFLY_URL=http://<частный-адрес>:8088` и пересоздайте сервисы. Разрешайте доступ только доверенным клиентам или через VPN. Частный адрес без HTTPS всё равно передаёт сессии входа и финансовую информацию открытым текстом.

<!-- coverage:deployment-domain-https -->
## Домен и HTTPS

Направьте `money.example.com` на сервер и задайте `FIREFLY_URL=https://money.example.com`. Укажите в `FIREFLY_TRUSTED_PROXIES` точный адрес или CIDR прокси, видимый приложению, затем выполните `docker compose up -d --wait --wait-timeout 600`. Не используйте `**`, если не контролируете весь прямой доступ. Сохраняйте `AUTHENTICATION_GUARD=web`: заголовки протокола от прокси не включают единый вход.

<!-- coverage:proxy -->
## Caddy, Nginx и Traefik

`proxy/Caddyfile` направляет HTTPS-домен на loopback-порт. Для `proxy/nginx.conf` укажите пути сертификатов; перед перезагрузкой выполните `nginx -t`. `proxy/traefik.yaml` — динамическая конфигурация file provider для уже установленного Traefik с указанным certificate resolver. Примеры предполагают прокси на Docker-хосте. Контейнерному прокси нужна контролируемая общая сеть или доступный адрес хоста: его `127.0.0.1` указывает на него самого.

## Данные и все параметры

Compose создаёт тома проекта `database`, `storage` и `uploads`. PostgreSQL 18 хранит данные в `/var/lib/postgresql`; Laravel storage — в `/var/www/html/storage`; отдельный том загрузок перекрывает `/var/www/html/storage/upload`. В storage находятся ключи подписи OAuth. `.env` содержит ключ шифрования вложений и сессий; потеря `FIREFLY_APP_KEY` может сделать зашифрованные данные нечитаемыми.

| Переменная | Назначение |
| --- | --- |
| `FIREFLY_VERSION` | Версия приложения `6.7.9`; тег образа — `version-6.7.9`. |
| `FIREFLY_PORT` | HTTP-порт loopback, `8088`. |
| `FIREFLY_URL` | Внешний URL со схемой и нестандартным портом, если нужен. |
| `FIREFLY_APP_KEY` | Секрет ровно из 32 символов; сохраняйте для восстановления. |
| `FIREFLY_DB_PASSWORD` | Уникальный пароль PostgreSQL. Задайте до первого запуска; правка только `.env` не меняет пароль роли в существующей БД. |
| `FIREFLY_CRON_TOKEN` | Отдельный 32-символьный секрет для плановых HTTP-задач. |
| `FIREFLY_SITE_OWNER` | Email оператора в некоторых сообщениях об ошибках; укажите подходящий контакт. |
| `FIREFLY_LANGUAGE` | Начальный язык `en_US` или `ru_RU`; пользователь может изменить его. |
| `FIREFLY_TRUSTED_PROXIES` | Доверенный IP/CIDR прокси; по умолчанию пусто. |
| `TZ` | Часовой пояс приложения, стандартно `UTC`. Сервис cron всегда запускает задачи в 03:00 UTC. |

Скрипты также принимают необязательные `FOSSARY_ENV_FILE`, `COMPOSE_PROJECT_NAME` и `FIREFLY_BACKUP_DIR`. По умолчанию это `.env`, проект `firefly-iii` и `backups/`. Если запускали `docker compose -p` с другим именем, экспортируйте тот же `COMPOSE_PROJECT_NAME` для каждого резервирования и восстановления. Ежедневный cron обслуживает повторяющиеся операции и автоматические бюджеты; импорт из банка и расписание резервирования настраиваются отдельно. SMTP не настроен; почтовые ссылки попадают в журналы, которые нужно защищать.

## Резервирование

```bash
bash backup.sh
```

Скрипт останавливает cron и приложение, делает логический дамп PostgreSQL и два архива хранилищ, добавляет `.env` и Compose, затем запускает только ранее работавшие сервисы. Архивы имеют режим 600 и уникальные имена. Зашифруйте копию на другой машине и регулярно проверяйте восстановление. Экспорт операций не является полной резервной копией.

<!-- coverage:restore -->
## Восстановление — заменяет финансовые данные

Используйте только доверенные архивы. Сохраните старый `.env`, особенно `FIREFLY_APP_KEY`, и совпадающие версии приложения и базы. На новом сервере запустите только БД и создайте контейнеры приложения без запуска:

```bash
docker compose up -d --wait database
docker compose create --no-deps firefly cron
```

Затем восстановите архив:

```bash
bash restore.sh /absolute/path/firefly-iii-<timestamp>.tar
```

Скрипт проверяет состав архива, создаёт страховочную копию, останавливает запись, пересоздаёт базу приложения, заменяет оба тома хранилища и ждёт healthcheck. Архивный `.env` автоматически не активируется. Проверьте остатки по счетам, операции, вложения и API-токены до открытия доступа. При сбое сервисы записи остаются остановленными; изучите журналы и устраните причину до запуска. Для другой машины нужны архивные секреты и исправленный внешний URL.

## Обновление

Прочитайте [release notes](https://github.com/firefly-iii/firefly-iii/releases) и [инструкцию обновления](https://docs.firefly-iii.org/how-to/firefly-iii/upgrade/docker/). Сохраните `.env`, Compose и проверенный архив. Остановите cron и приложение, измените только `FIREFLY_VERSION` на изученную закреплённую версию, загрузите и запустите её:

```bash
bash backup.sh
docker compose stop cron firefly
# Измените FIREFLY_VERSION в .env; сохраняйте мажорную версию БД.
docker compose pull firefly
docker compose up -d --wait --wait-timeout 600
docker compose logs --tail=100 firefly
```

Миграции базы выполняются при запуске автоматически. Проверьте остатки, скачивание чеков, плановые задачи и API. Для мажорного обновления PostgreSQL нужен отдельный план экспорта и импорта; не подключайте существующий каталог к другой мажорной версии.

## Откат

1. Закройте внешний доступ, остановите `cron` и `firefly`.
2. Верните предыдущие Compose и `.env`, сохраняя правильный ключ шифрования и ту же мажорную версию БД. Укажите прежний `FIREFLY_VERSION`.
3. Загрузите прежний образ, выполните `docker compose up -d --wait database`, затем `docker compose create --no-deps firefly cron`. Оставьте приложение остановленным, чтобы старый код не мигрировал текущую базу.
4. Запустите `bash restore.sh /path/to/pre-upgrade.tar`. Страховочная копия сохранит текущее состояние, затем прежние база и хранилища заменят его.
5. Проверьте вход, остатки, операции, вложения и API, затем откройте прокси. Не считайте простую смену образа на старый поверх мигрировавшей базы безопасным откатом.

<!-- coverage:removal -->
## Остановка и удаление

`docker compose down` сохраняет тома. Для полного удаления после проверки внешней копии выполните `docker compose down --volumes --remove-orphans`. Команда уничтожает финансовые записи, вложения и ключи OAuth. `.env` и локальные архивы удаляйте отдельно, когда они больше не нужны.

Перед изменением модели безопасности изучите официальные руководства [по резервированию](https://docs.firefly-iii.org/how-to/firefly-iii/advanced/backup/) и [по аутентификации](https://docs.firefly-iii.org/how-to/firefly-iii/advanced/authentication/).
