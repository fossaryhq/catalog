### Порт 53 уже занят

Проверьте точный адрес слушателя, а не только номер порта:

```bash
sudo ss -luntp | grep ':53 '
docker compose logs --tail=100 pi-hole
```

`127.0.0.53` у `systemd-resolved` отличается от адреса рецепта по умолчанию
`127.0.0.1`. Если другая служба слушает `127.0.0.1:53` или все интерфейсы,
выберите свободный конкретный адрес LAN/VPN либо перенастройте конфликтующую
службу. Не меняйте системный резолвер, пока не подготовили рабочую замену.

### Контейнер остаётся unhealthy

Healthcheck официального образа направляет DNS-запрос собственному процессу
FTL:

```bash
docker compose ps
docker inspect --format '{{json .State.Health}}' "$(docker compose ps -q pi-hole)"
docker compose logs --tail=150 pi-hole
```

Если журнал сообщает о повреждённой базе, восстановите проверенный архив тома.
При ошибке прав или диска проверьте том и свободное место.

### Устройство в LAN не разрешает имена

```bash
docker compose port pi-hole 53/udp
nslookup pi.hole 192.168.1.10
```

Если Compose показывает `127.0.0.1`, укажите реальный LAN-адрес в
`PIHOLE_DNS_BIND` и пересоздайте контейнер. Разрешите в LAN-файрволе и TCP, и
UDP 53. Проверьте, что роутер выдаёт тот же адрес по DHCP.

### Реклама видна или сайт перестал работать

Проверьте журнал запросов: если там нет запросов клиента, он может использовать
собственный DNS-over-HTTPS или другой DNS-сервер. Сетевая фильтрация не удалит
контент, который приходит с того же домена, что и страница. Если сайт сломался,
найдите заблокированный домен в Query Log и добавьте в разрешённые только его.
Не отключайте всю блокировку из-за одного ложного срабатывания.

### Не подходит пароль веб-панели

Убедитесь, что в `.env` задан нужный `PIHOLE_WEB_PASSWORD`, и пересоздайте
контейнер командой `docker compose up -d`. Переменная
`FTLCONF_webserver_api_password` задаёт пароль при каждом запуске. Не оставляйте
пароль в истории команд и не публикуйте вывод `docker inspect`.

### Восстановленный сервер выглядит новым

Убедитесь, что `PIHOLE_VOLUME` указывает на тот же том, что и backup, а архив
содержит `pihole.toml` и `gravity.db`:

```bash
docker compose config
docker volume inspect pi-hole-data
tar -tzf ./backups/pi-hole-YYYYMMDDTHHMMSS.NNNNNNNNNZ.tar.gz | grep -E 'pihole.toml|gravity.db'
```

Не создавайте новые списки, пока не найдёте правильный том или не восстановите
архив до обновления.
