## Подготовка сервера

Используйте Ubuntu 22.04+ или Debian 12+, Docker Engine и Compose v2.24+. Планируйте одно ядро, минимум 512 МБ RAM (рекомендуется 1 ГБ) и 2 ГБ диска плюс статьи и изображения. Образы ARM64 и ARMv7 существуют, но в этом прогоне не проверялись.

```bash
mkdir -p ~/services/wallabag
cd ~/services/wallabag
# Скопируйте сюда все файлы рецепта, включая proxy/ и скрипты.
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
openssl rand -hex 24
```

Запишите первое значение в `WALLABAG_SECRET`, второе — в `WALLABAG_ADMIN_PASSWORD`. Значения должны различаться. Инициализатор отклоняет шаблонный пароль, стандартный пароль upstream и пароли короче 16 символов. Шаблонный секрет приложения также отклоняется. Скрипты подключают `.env` как доверенную конфигурацию shell; рекомендуемым шестнадцатеричным значениям экранирование не нужно.

| Параметр | Назначение |
| --- | --- |
| `WALLABAG_VERSION` | Точный тег образа, первоначально `2.6.15`. |
| `WALLABAG_PORT` | Порт хоста на loopback, по умолчанию `8087`. |
| `WALLABAG_URL` | Канонический origin браузера, первоначально `http://localhost:8087`; за прокси задайте внешний HTTPS-origin. |
| `WALLABAG_SECRET` | Случайный секрет приложения и сессий; сохраняйте вместе с копией. |
| `WALLABAG_ADMIN_PASSWORD` | Пароль администратора, задаваемый инициализацией. Сохраняйте имя учётной записи `wallabag`; для смены пароля измените это поле и пересоздайте стек. |
| `WALLABAG_LOCALE` | Язык интерфейса по умолчанию: `en` или `ru` для этих руководств. Личные настройки могут его переопределять. |
| `TZ` | Часовой пояс ОС контейнера, по умолчанию `Etc/UTC`; PHP использует UTC для сохраняемых дат. |
| `WALLABAG_BACKUP_DIR` | Необязательный абсолютный каталог копий; пустое значение использует `backups/` рядом с рецептом. |

Именованный том `data` содержит SQLite в `/var/www/wallabag/data/db` и другие данные приложения. `images` хранит кешированные изображения в `/var/www/wallabag/web/assets/images`. Оба тома привязаны к проекту Compose; сохраняйте имя проекта. Конфигурация контейнера и кеш пересоздаются из закреплённого образа и `.env`.

## Запуск и вход

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 600
curl --fail http://127.0.0.1:8087/api/info
```

Сервис `initialize` должен успешно завершиться до запуска `wallabag`. Он выполняет официальную команду миграции, затем меняет стандартный пароль администратора. Опубликованный веб-сервис не принимает стандартные учётные данные upstream ни на одном этапе запуска. Регистрация остаётся закрытой.

На своём компьютере выполните `ssh -L 8087:127.0.0.1:8087 user@server`, откройте `http://localhost:8087` и войдите как `wallabag` с паролем из `.env`. Измените email администратора в настройках аккаунта. Не удаляйте и не переименовывайте эту управляемую развёртыванием учётную запись. Изменение пароля через интерфейс заменится при следующей инициализации; меняйте его в `.env`. Дополнительных пользователей можно создавать официальными средствами администратора/консоли.

SMTP, Redis, RabbitMQ, SSO-провайдер и мобильный клиент не настроены. Встроенный второй фактор TOTP/email требует отдельной настройки; проверьте восстановление доступа до включения. Отправка писем недоступна до настройки SMTP.

## VPS

<!-- coverage:deployment-vps -->

Задайте `WALLABAG_URL=https://read.example.com`, настройте DNS и HTTPS-прокси, затем пересоздайте стек. Разрешите в firewall только SSH, HTTP и HTTPS. Оставьте порт 8087 на loopback. Шифруйте копии и храните экземпляр вне сервера.

## Доверенная локальная сеть

<!-- coverage:deployment-lan -->

Используйте SSH-туннель или HTTPS-прокси, доступный из доверенной LAN/VPN. Если намеренно публикуете приватный интерфейс, ограничьте его firewall и задайте в `WALLABAG_URL` точный адрес пользователей. Не открывайте парольный вход по HTTP недоверенной сети.

## Домен и HTTPS

<!-- coverage:deployment-domain-https -->

Выберите пример прокси на хосте в `proxy/`. Caddy получает сертификаты; Nginx нужны пути к сертификатам; Traefik — точка входа `websecure` и resolver `letsencrypt`. Все примеры направляют запросы на `127.0.0.1:8087`. Контейнерному прокси нужны общая сеть и адрес `wallabag:80`, а не собственный loopback.

Замените пример домена, задайте совпадающий HTTPS `WALLABAG_URL` и выполните `docker compose up -d --wait --wait-timeout 600`. Правильно передавайте `Host` и `X-Forwarded-Proto`. Пример Nginx допускает запросы до 50 МБ. Проверьте вход и получение статьи через итоговый origin; внешний прокси и выдача сертификата не проверялись в native smoke.

## Резервная копия

<!-- coverage:backup -->

```bash
./backup.sh
```

Сначала дождитесь окончания инициализации. Скрипт останавливает веб-приложение, архивирует оба полных тома с активными `.env` и Compose и запускает приложение, только если оно работало. Приватный архив — `backups/wallabag-<timestamp>.tar`. Копируйте SQLite и WAL вместе при остановленной записи; личный экспорт статей не содержит все учётные записи, OAuth-клиенты и настройки.

Зашифруйте архив и скопируйте вне сервера. В нём приватные статьи, кешированные изображения, аккаунты, токены и управляемый развёртыванием пароль администратора.

## Восстановление

<!-- coverage:restore -->

**Восстановление заменяет оба тома.** Используйте доверенный архив и совпадающую версию приложения. На новом хосте скопируйте рецепт и сначала сравните архивные `configuration.env` и `compose.yaml` с активной конфигурацией. Архивная конфигурация автоматически не активируется; при инициализации задаётся пароль администратора из активного `.env`.

```bash
docker compose up -d --wait --wait-timeout 600
./restore.sh ./backups/wallabag-TIMESTAMP.tar
curl --fail http://127.0.0.1:8087/api/info
```

Скрипт проверяет состав архива, создаёт страховочную копию, заменяет полные тома данных/изображений и ждёт healthcheck. При ошибке замены приложение остаётся остановленным. Войдите, откройте приватную статью, проверьте теги и кешированные изображения либо API-доступ мобильного клиента. Smoke-тест amd64 удаляет оба исходных тома перед восстановлением и проверяет OAuth-клиент, статью, теги, отклонение анонимного доступа и маркер в томе изображений.

## Обновление

<!-- coverage:update -->

Прочитайте [release notes](https://github.com/wallabag/wallabag/releases), создайте копию вне сервера и измените `WALLABAG_VERSION` на проверенный точный тег. Затем:

```bash
docker compose pull
docker compose up -d --wait --wait-timeout 600
docker compose logs --tail=100 initialize wallabag
```

Инициализация применяет миграции до запуска веб-приложения и снова задаёт активный пароль администратора. После обновления проверьте вход, сохранённую статью, теги и API-клиент. Храните копию до обновления. Не используйте `latest` и не предполагайте, что старый образ прочитает мигрировавшую базу.

## Откат

<!-- coverage:rollback -->

1. Сохраните архив до обновления и подходящие рецепт и конфигурацию.
2. Остановите запись: `docker compose stop wallabag`.
3. Задайте в `.env` старую точную версию образа и верните подходящие изменения Compose. Скачайте старый образ.
4. Выполните `docker compose create`, не запуская старый инициализатор или приложение на мигрировавшей базе.
5. Выполните `./restore.sh ./backups/wallabag-BEFORE-UPDATE.tar`. Инициализация и приложение запустятся только после замены. Проверьте вход, приватные статьи, теги, изображения и API-доступ.

Страховочная копия читает остановленные тома без запуска старого приложения на новых данных. Восстановление данных не возвращает архивный пароль администратора автоматически: явно сравните активный `.env`.

## Остановка и удаление

<!-- coverage:removal -->

`docker compose down` удаляет контейнеры и сохраняет тома. После проверки зашифрованной внешней копии `docker compose down --volumes` навсегда удаляет аккаунты, статьи, настройки, OAuth-клиенты и кешированные изображения. Удаление каталога рецепта также удаляет локальные копии и конфигурацию. Не используйте глобальную очистку Docker.
