## Запуск и состояние базы

```bash
docker compose ps --all
docker compose logs --tail=150 vikunja database permissions
curl --fail http://127.0.0.1:3456/health
```

`permissions` должен завершиться с кодом 0: это разовое назначение владельца, а не веб-сервис. PostgreSQL и Vikunja должны стать healthy. Встроенный healthcheck не требует shell или curl внутри минимального образа. При старте выполняются миграции; дождитесь healthy до создания аккаунтов и работы с API.

## Ошибка аутентификации БД или блокировка SQLite

Рецепт использует PostgreSQL. Если в логах указаны SQLite или `database is locked`, проверьте, что запускается этот Compose и контейнер получает `VIKUNJA_DATABASE_TYPE=postgres`. Пароль `VIKUNJA_DB_PASSWORD` должен совпадать с паролем созданной роли PostgreSQL. Правка начальных переменных не меняет существующие реквизиты; не удаляйте том базы для исправления пароля.

## Не удаётся зарегистрироваться или войти

Публичная регистрация намеренно выключена. Создайте аккаунт через `vikunja user create` внутри контейнера; начального пароля нет. Поддерживаемые команды восстановления смотрите через `docker compose exec vikunja /app/vikunja/vikunja user --help`. До использования почтового восстановления и напоминаний настройте SMTP. Строка `Pro features have been disabled` нормальна для бесплатного ядра и не мешает спискам или канбану.

## Неверный адрес или подключение настольного клиента

`VIKUNJA_PUBLIC_URL` должен точно совпадать с доступным адресом браузера, включая схему, порт и завершающий слеш. После правки пересоздайте приложение. Настольному клиенту нужен тот же URL сервера. HTTPS-прокси должен правильно передавать `Host` и `X-Forwarded-Proto`. Смена секрета сервиса аннулирует выданные токены; при обычном перезапуске и восстановлении сохраняйте прежнее значение.

## Ошибки загрузки или прав

Проверьте свободное место хоста Docker и оба тома. Приложение пишет в `/data` с UID/GID `1000:1000`; смотрите состояние `permissions`, а не открывайте запись всем и не запускайте приложение от root. Корневая файловая система намеренно доступна только для чтения. Запрос должен помещаться в лимит прокси и лимит файла Vikunja (по умолчанию 20 МБ).

## Ошибка backup или restore

Используйте полный архив из `backup.sh`, а не отдельный дамп или архив тома приложения. Проверьте место, логи PostgreSQL и права на архив. Восстановление заменяет public-схему базы и файлы приложения; после ошибки замены оставьте Vikunja остановленной до завершения восстановления. Сравнивайте архивную конфигурацию с активным `.env`, не раскрывая реквизиты, и используйте совместимые версии. Не понижайте PostgreSQL на существующем физическом каталоге.
